# Navexa AgeCheck for WooCommerce: agent notes

The plan is §5 of `~/.cache/agecheck-gap-2026-11-13/design-final.md` (layout, milestones W0-W5, hooks table). The engine contract is in the tax repo's `proto/agecheck/v1/verification.proto` and CLAUDE.md (AgeCheck sections). README.md has the commands.

## Rules
- **Fail closed.** Any `ConnectError`, a missing key, an unknown mode or a paused install refuses: never admit, never release. There is no fail-open setting.
- **Server decides.** Admission needs `GetVerification` PASSED with a clearing pass class; release needs `GetClearance` CLEARED. Both go through `Mode::accepts_livemode()`, and release also through `Mode::may_auto_release()`. Browser-sent ids are hints only.
- **No PII or secrets in logs.** Use `Client::log()` with ids and codes only. Never log a key, a request body, `ConnectError::server_message()` or a hosted URL.
- **Request paths make one attempt, with no sleeps.** Action Scheduler jobs reschedule on `ConnectError::is_retryable()` after `retry_after()`. A bodiless 500 or Cloudflare 520-526 reads as `unavailable` (retryable); a Connect body's own code always wins.
- **HPOS only.** Use `wc_get_order`, order CRUD meta and `wc_get_orders`. Never post meta or `WP_Query` on orders.
- **Names.** Options are `navexa_agecheck_*`, order meta `_navexa_agecheck_*`, hooks `navexa_agecheck_*`, namespace `Navexa\AgeCheck`, text domain `navexa-agecheck-for-woocommerce`.
- **Settings loads only on WooCommerce settings screens.** `Settings` extends `WC_Settings_Page`, so never reference it from checkout code; use `Options`.
- **Site address is `Install::home()`** (the raw `home` option, which still honours `WP_HOME`), never `home_url()`. Multilingual plugins (TranslatePress, WPML) filter `home_url` per request on the front end only, so a fingerprint or origin built from it pauses checkout while admin screens look fine.
- **Order external ids** are `wc:{install_id}:{blog_id}:{order_id}`. They are stored in order meta at bind and never recomputed, because `Install::confirm_site()` rotates the install_id.
- **`add_option()` is not a mutex.** WordPress runs `INSERT ... ON DUPLICATE KEY UPDATE` after a read, so two racing writers both "win". Locks and webhook dedupe need an atomic primitive, such as a plain `INSERT` into a plugin table with a unique key, or `$wpdb->query( "INSERT IGNORE ..." )` and a check of rows affected.

## Pre-payment (W2)
- **The browser holds nothing that admits an order.** The verification id and the checkout guard live in the WooCommerce session (`Checkout\Session`); the start/refresh answer carries only `{v, status, hosted_url?, message?}`. Never put a vid, guard or key in the page, the cart data or a log line (log `vid=` ids and verdict codes only; never the hosted URL, the sid or an address).
- **Ship-to identity is `ShipTo`.** Normalize every address the engine sees with `ShipTo` (`engine_address()`), and compare with `mac()`/`equals()`. `engine_canonical()` is pinned byte for byte by `tests/phpunit/fixtures/ship-to-vectors.json`, exported from the engine; regenerate it from the engine if `ShipToCanonical` changes, never edit it by hand.
- **Rate limits key on the WooCommerce customer id**, not the sid: concurrent first starts each mint their own sid (found in wp-env). The counter table is the only rate-limit store; never a transient or `add_option()`. Counter keys and the recent-start IP fingerprints are HMACs keyed from the guard secret, never plain hashes (IPv4 is brute-forceable). A missing table or secret answers `RateLimit::UNAVAILABLE` ("temporarily unavailable"), never "too many attempts".
- **Seams for W1** (binding, holds): the guarded verification's id sits alone in the session key `navexa_agecheck_vid` (`Session::KEY_VID`, set and cleared with the guard; `Gate::admitted_verification_id()` has it for the current request). Bind it, then drop it and the guard (or `Session::forget_verification()`). Store `_navexa_agecheck_vid` plus the bound ship-to as `_navexa_agecheck_shipto_mac` (= `ShipTo::from_order($order)->mac()`) or W1's `_navexa_agecheck_ship_to` (SHA-256 of `ShipTo::canonical()`): a resumed bound order is admitted only at that ship-to, and without either it is refused and dropped. Requirement rules plug in through the `navexa_agecheck_cart_required` / `navexa_agecheck_order_required` filters (default: everything restricted). A bound order whose ship-to changed is dropped with `Session::forget_verification_of($vid)`, so a check the shopper already passed for the new ship-to survives. Order-pay rules must skip the order the Store API cart checkout is placing (`Blocks::is_cart_checkout($order)`; it may be a reused pending/failed order). Pickup has one list, `Gate::pickup_method_ids($order|null)` (WooCommerce's local-pickup methods plus defaults, through `navexa_agecheck_pickup_methods`); the hold path must use `Gate::order_is_pickup()`.
- Built assets (`assets/js/`, `assets/build/`) are committed and CI rebuilds them: run `npm run build` after touching `assets/src/`.

## Style
- WordPress Coding Standards (`phpcs.xml.dist`): long array syntax, Yoda conditions, snake_case methods, a docblock on everything. PHP 7.4 syntax only. `includes/` is PSR-4, so the WordPress file-name sniff is off there.
- Tests are Brain Monkey unit tests in `tests/phpunit/Unit` (in-memory options, transients, HTTP, WC session/cart/customer and a counter-table `wpdb` in `TestCase`), plus `tests/wp-env/smoke.php` and `tests/wp-env/prepayment.mjs` for behaviour that only real WooCommerce shows, and `tests/e2e/prepayment-browser.mjs` for the popup. The mock engine (`tests/mock-agecheck/server.mjs`) gains RPCs as milestones need them. Keep its answers proto3 JSON: lowerCamelCase, zero values omitted.
- Docker for PHP (`php:8.3-cli`, `php:7.4-cli`, `composer:2`) with `-u "$(id -u):$(id -g)"`.
